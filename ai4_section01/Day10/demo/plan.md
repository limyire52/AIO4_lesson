# community-demo 구현 계획

- 작성일: 2026-10-27
- 버전: v1.0
- 상태: 사용자 승인으로 최종 확정·코드 구현 및 로컬 검증 완료 — 실제 호스팅 검증은 미실행
- 기준 문서: [prompt.md](./prompt.md)
- 이번 작업 범위: 승인된 계획에 따른 코드 생성·테스트·실행 및 최신 배포 문서 작성.

## 1. 목표와 범위

회원 인증이 있는 게시판을 만든다. 로그인 후 환영 안내를 거쳐 게시판에 진입하고, 제목 목록·검색·10개 단위 페이징·본문 내 상세 보기·게시글과 댓글 관리·표현 마스킹·신고 및 관리자 처리를 제공한다.

추가 승인된 비밀번호 해시, 안전한 세션, 검색, 본인 댓글 관리, 신고 상태·메모, 반복 요청 제한은 모두 필수 범위다. SNS 로그인과 실제 비밀번호 재설정은 향후 범위이며 비밀번호 찾기는 목업이다. 공개 게시판, 대댓글, 좋아요, 파일 첨부, 이용자 제재, 자동 통보는 포함하지 않는다.

## 2. 확정 기술과 무료 배포 기준

사용자 지정: Python + FastAPI + Uvicorn + SQLite3. 화면은 기본 HTML·CSS·JavaScript와 fetch로 구성한다. Java·Spring Boot·Thymeleaf·PostgreSQL 제안을 제거한다. 별도 DB 서버, ORM, 프런트엔드 프레임워크, Node.js 빌드, Docker, Redis, 유료 API는 사용하지 않는다.

- Python 표준 sqlite3로 저장하고 표준 unittest로 테스트한다. FastAPI가 사용하는 Pydantic·Starlette는 의존성으로 함께 설치된다.
- 추가 런타임 라이브러리는 argon2-cffi(기존 승인된 비밀번호 해시)와 regex(정규식 실행 시간 제한)만 사용한다. 자체 암호 구현이나 무제한 정규식 실행으로 대체하지 않는다.
- Jinja2와 python-multipart는 사용하지 않는다. 정적 HTML 및 JSON 요청으로 구현한다. 필요 없는 템플릿·폼 처리 의존성을 추가하지 않는다.
- 테스트용 HTTP 클라이언트 httpx는 개발 의존성으로 분리한다. PythonAnywhere 배포 CLI pythonanywhere는 호스팅 설정 도구이며 앱 런타임에는 필요 없다. 모두 유료 서비스가 아니다.
- 최초 관리자 생성은 getpass 기반 명령, 세션 절대 만료는 설정 가능한 2시간을 기본값으로 한다. 본인 게시글 편집 원문은 서버에서 소유권·비밀번호를 확인한 전용 응답에만 제공한다. 일반 조회는 항상 마스킹한다. 본인 댓글 편집 원문은 세션·소유권을 확인한다.

PythonAnywhere 배포 제약:

- 공식 ASGI 베타 배포 경로를 사용한다. 일반 WSGI 설정에 FastAPI를 직접 연결하지 않는다. 콘솔에서 Uvicorn을 임의 포트로 계속 실행하는 방식에 의존하지 않는다.
- 계정의 무료 ASGI 사용 가능 여부와 실제 과금 조건을 최소 앱으로 먼저 확인한다. 공식 문서는 장기 ASGI 가격이 미정이라고 명시하므로 영구 무료를 보장하지 않는다. 무료 불가 시 유료 전환이나 Flask/Django 변경을 자동 진행하지 않고 사용자에게 선택을 요청한다.
- 기본 PythonAnywhere 서브도메인과 HTTPS를 사용한다. 도메인 구매와 별도 인증서 서버를 요구하지 않는다.
- 무료 계정 안내는 웹 앱 1개·워커 1개·만료 1개월·디스크 512 MiB·CPU 제한을 명시한다. 계정에서 실제 할당량과 연장 방법을 확인한다.
- 신규 무료 계정의 예약 작업을 전제로 하지 않는다. 만료 데이터는 수동 정리 명령과 요청 시 제한된 정리로 처리한다. 상주 스케줄러·백그라운드 큐·WebSocket은 도입하지 않는다.
- ASGI의 정적 파일 매핑 제한 때문에 앱에서 /static의 명시한 파일만 제공한다. DB·환경설정·소스 디렉터리 전체를 정적 마운트하지 않는다.
- 외부 인터넷은 제한될 수 있으므로 필터 목록은 개발 시 조사하여 출처와 함께 배포한다. 실행 중 외부 검색이나 다운로드를 수행하지 않는다.
- SQLite는 소규모 학습·시연 용도로 제한한다. 호스트 공식 문서는 파일 시스템 성능상 운영용 DB로 권장하지 않는다. 고트래픽 서비스로 설명하지 않는다.
## 3. 구조와 산출물

제안 구조는 단일 FastAPI 앱에서 정적 HTML과 JSON API를 같은 출처로 제공한다. 인증 쿠키와 CSRF 방어를 일관되게 적용하고, 서버의 서비스 계층에서 소유권·관리자 권한·비밀번호 재확인을 검증한다.

| 영역 | 책임 | 예정 산출물 |
|---|---|---|
| 인증·보안 | 가입, 해시, 세션, CSRF, 요청 제한 | auth/security 모듈, 보안 설정 |
| 게시판 | 검색·페이지·상세·작성·수정·논리 삭제 | post 모듈 |
| 댓글 | 글별 조회·작성·본인 수정·삭제 | comment 모듈 |
| 표현 필터 | 규칙 검증·마스킹·관리 | moderation/filter 모듈 |
| 신고 | 접수·관리자 조회·상태·메모 | report 모듈 |
| 데이터 | 7개 테이블·인덱스·제약·트랜잭션 | DB 마이그레이션 |
| 화면 | 한국어 HTML·간단한 스타일·영역 전환 | static |
| 검증·운영 | 통합 테스트, 실행·초기화·제한 문서 | tests, README, 검증 결과 |

레이어는 컨트롤러 → 서비스 → 저장소로 나눈다. 사용자 입력 DTO와 응답 DTO를 분리하여 DB 엔티티 전체를 응답으로 반환하지 않는다. 경로는 app/main.py, app/routers, app/services, app/repositories, static, migrations, tests, scripts로 구성한다.

## 4. 단계별 구현 순서와 완료 조건

| 단계 | 작업 | 선행 단계 | 완료 조건 | 요구사항 연결 |
|---|---|---|---|---|
| P0 계획 확정 | 사용자 구현 승인 반영, 무료 계정 확인은 실제 배포 전 수행 | 없음 | 구현 계획 최종 확정, 호스팅 미검증 표시 | 작업 원칙, 이번 피드백 요청 |
| P1 기반 구성 | Python venv·의존성·설정 분리·오류 형식·SQLite 연결 | P0 | 로컬 기동, 비밀값 없는 설정 예제 제공 | 데이터/오류 처리 |
| P2 데이터 모델 | 7개 테이블·제약·인덱스·시드·정리 명령 | P1 | 빈 DB 마이그레이션 성공, 제약 및 롤백 검증 | ERD, 테이블 구조 |
| P3 회원·보안 | 가입·로그인·로그아웃·목업·세션·CSRF·공통 요청 제한 | P2 | 정상 인증 및 만료/폐기/비인가·제한 테스트 통과 | AUTH-01~04, SECURITY-01~02 |
| P4 표현 필터 | 초기 자료 조사·출처 기록·규칙 검증·마스킹 서비스 | P2 | 제목·본문·댓글 마스킹과 위험 패턴 제한 검증 | FILTER-01~02 |
| P5 게시글·검색 | 작성·목록·10개 페이징·검색·상세·재확인·수정·삭제 | P3, P4 | 소유권·비밀번호·검색·삭제 경계 시나리오 통과 | POST-01~04, SEARCH-01 |
| P6 댓글 | 글별 목록·작성·본인 수정·삭제·요청 제한 | P5 | 타인 변경 거부, 수정 마스킹, 삭제 글 접근 거부 | COMMENT-01~02 |
| P7 신고·관리 | 신고·관리자 권한·규칙 추가/삭제·상태/메모 저장 | P6 | 일반 사용자 접근 차단, 삭제 대상 신고 조회 가능 | REPORT-01~03, FILTER-03 |
| P8 화면 완성 | 환영 흐름·body 숨김 영역·인라인 입력·모바일 정리 | P3~P7 | 전체 사용자·관리자 흐름 직접 확인 | FLOW-01~02, 화면 구성 |
| P9 최종 검증 | 요구사항 대조·통합 검증·실행 문서·누락 수정 | P8 | prompt.md의 모든 인수 기준에 결과·근거 기록 | 필수/추가 인수 기준 |

기본 화면 골격은 P1부터 마련하고 각 기능 단계에서 연결한다. P8은 화면 작업을 처음 시작하는 단계가 아니라 통합과 마무리 단계다. 실패한 단계는 보완 후 진행하며, 완료 여부를 계획과 검증 보고서에 기록한다.

## 5. 데이터 구현 계획

ERD와 컬럼의 기준은 prompt.md 12~13절이다. 이 문서에서 다른 스키마를 중복 정의하지 않고 아래 구현 작업으로 연결한다.

1. users → posts/comments/sessions/filter_rules → reports → rate_limit_buckets 순으로 마이그레이션한다.
2. 이메일 정규화·유일성, 역할/규칙 유형/신고 상태 범위, 신고 대상 XOR, 내용 길이와 필수값을 검증한다.
3. UUID와 UTC 저장, 생성/수정 시각, 선택적 삭제/처리 시각을 매핑한다.
4. 게시글과 연결 댓글의 논리 삭제를 트랜잭션으로 묶는다. 삭제 중 댓글 생성도 부모 글 상태 확인과 BEGIN IMMEDIATE의 짧은 쓰기 트랜잭션에서 상태를 재확인하여 경합을 막는다.
5. 신고의 대상 관계는 유지하고 일반 조회에서 삭제 데이터를 제외한다. 신고 상태·메모·담당자·시각은 한 트랜잭션으로 갱신한다.
6. 요청 제한 카운터는 원자적으로 갱신한다. 비밀번호 검증 실패 시 카운터까지 롤백되지 않도록 업무 트랜잭션과 분리한다.
7. 만료 세션·제한 카운터 정리 명령과 개발 DB 초기화 절차를 제공한다. 초기화는 명시적으로 실행하며 운영 데이터에는 자동 적용하지 않는다.

## 6. 서버 인터페이스 계획

아래 경로는 구현 계약 초안이며 확정 스택의 관례에 맞춰 조정할 수 있다. 경로가 바뀌어도 권한과 동작은 유지한다.

| 인터페이스 | 동작 | 필수 검증 |
|---|---|---|
| POST /api/auth/signup | 가입 | 이메일·닉네임·비밀번호, 역할은 서버에서 USER 지정 |
| POST /api/auth/login | 로그인·세션 발급 | 계정/IP 실패 제한, 일반화된 실패 안내 |
| POST /api/auth/logout | 로그아웃 | 세션 폐기·CSRF |
| GET /api/auth/me | 현재 사용자 | 유효 세션, 최소 사용자 정보만 반환 |
| GET /api/posts | 목록·검색·페이지 | 로그인, 검색 대상 허용목록·페이지 범위 |
| POST /api/posts | 글 작성 | 로그인·CSRF·입력·작성 제한 |
| GET /api/posts/{id} | 마스킹 상세 | 로그인·삭제 여부 |
| POST /api/posts/{id}/edit-access | 편집 원문 요청 | 소유권·비밀번호·재확인 실패 제한, 작성자 전용·비밀번호 재확인 |
| PATCH /api/posts/{id} | 수정 | 소유권·비밀번호·CSRF·입력·삭제 여부 |
| POST /api/posts/{id}/delete | 논리 삭제 | 소유권·비밀번호·CSRF·트랜잭션 |
| GET/POST /api/posts/{id}/comments | 댓글 조회/작성 | 로그인·부모 글 상태, 작성 시 CSRF·요청 제한 |
| PATCH/DELETE /api/comments/{id} | 댓글 수정/삭제 | 소유권·CSRF·부모 글 상태, 수정 입력 검증 |
| POST /api/reports | 신고 | 로그인·CSRF·존재하는 활성 대상·사유·요청 제한 |
| GET/POST /api/admin/filter-rules | 규칙 조회/추가 | 관리자, 추가 시 CSRF·중복/정규식 검사 |
| DELETE /api/admin/filter-rules/{id} | 규칙 삭제 | 관리자·CSRF |
| GET /api/admin/reports 및 /{id} | 신고 목록/상세 | 관리자·상태 필터 |
| PATCH /api/admin/reports/{id} | 상태·메모 저장 | 관리자·CSRF·상태/메모 검증 |

조회에는 부작용을 두지 않는다. 비밀번호를 URL이나 검색 파라미터에 넣지 않는다. 오류는 잘못된 입력 400, 미인증 401, 권한 부족 403, 없는/삭제된 일반 대상 404, 중복 409, 제한 초과 429를 기준으로 통일한다. UI에는 한국어 안내를 제공한다.

## 7. 간단한 화면 구현 계획

```text
로그인 ── 회원가입 / 비밀번호 찾기(목업)
  ↓ 성공
환영 안내 → 게시판으로 이동
  ↓
게시판
  상단: community-demo | 닉네임 | 관리(관리자만) | 로그아웃
  검색: [제목/내용/통합] [검색어] [검색] [초기화]
  목록: 제목만 표시, 기본 10개
  하단: [이전] 페이지 [다음] [글쓰기]
  숨김 상세 영역: 제목 / 본문 / 본인 수정·삭제 / 신고 / 닫기
    댓글: 목록 / 본인 수정·삭제 / 신고 / 입력·등록
  인라인 편집 영역: 제목 / 내용 / 비밀번호(글 수정) / 저장·취소
  인라인 확인 영역: 신고 사유 또는 삭제 확인·비밀번호

관리자: [표현 규칙] [신고 관리]
  규칙: 입력·추가 / 규칙 목록·삭제
  신고: 상태 필터 / 목록 / 상세 / 상태·메모·저장
```

- 팝업·모달·새 창 없이 현재 body의 hidden 영역을 전환한다.
- 글 선택 변경/삭제/닫기 시 이전 댓글·입력·오류 상태를 정리한다. 뒤늦은 응답이 다른 글을 덮어쓰지 않게 요청을 취소하거나 선택 ID를 검사한다.
- 입력 레이블과 키보드 조작을 지원하고, 모바일 한 열 배치·저장 중 중복 클릭 방지·빈 화면 안내를 적용한다.
- 관리자 메모·해시·세션·타인의 편집 원문은 화면이나 응답에 노출하지 않는다.

## 8. 마스킹과 초기 자료 조사

- 초기 키워드는 구현 시점에 외부 자료를 조사하여 출처 URL·확인 날짜·재사용 조건·오탐 검토를 기록한다. 현재 계획 단계에서 최신 목록을 수집한 것으로 간주하지 않는다.
- 원문은 서버에 보관하고 일반 조회 응답 생성 시 현재 규칙으로 마스킹한다. 규칙 추가·삭제 후 기존 글에도 반영한다.
- 규칙 우선순위 내림차순/id 순으로 원문상의 일치 구간을 수집하고 겹치는 구간을 병합한 뒤 치환한다. 치환된 문자열을 재검색하지 않아 중첩 처리 결과를 안정화한다.
- 한국어 WORD 모드는 단순 영문 단어 경계에 의존하지 않고 유니코드 문자·숫자 경계를 정의해 테스트한다.
- 정규식은 제한된 엔진이나 실행 제한을 지원하는 방식으로 구현한다. 패턴 길이 제한만으로 실행 안전성이 확보됐다고 판단하지 않는다.
- 인터넷 접근이 불가능하면 해당 요구사항을 미완료로 보고한다. 임시 목록을 최종 목록으로 위장하지 않는다.

## 11. SQLite3 물리 설계와 동시성

- prompt.md의 논리 ERD와 7개 테이블 관계는 유지한다. UUID는 TEXT, 문자열·본문·UTC ISO 8601 시각은 TEXT, BOOLEAN은 INTEGER(0/1), 카운터는 INTEGER로 저장한다.
- SQLite는 VARCHAR(n)의 길이를 자동 강제하지 않으므로 length() CHECK와 서버 검증을 함께 둔다. 시간 형식은 고정하고 애플리케이션에서 생성·해석한다.
- 모든 연결에서 PRAGMA foreign_keys=ON, busy_timeout을 설정한다. 기본 journal_mode=DELETE를 사용하고 호스팅 파일 시스템을 확인하지 않은 WAL 설정은 금지한다.
- 연결은 동기 저장소 작업 내부에서 열고 닫는다. 연결 객체를 전역 공유하거나 스레드 사이에 전달하지 않는다. 동기 DB·해시 작업을 이벤트 루프에서 직접 실행하지 않도록 동기 라우트 또는 스레드풀 경계를 사용한다.
- SQLite에서 SELECT FOR UPDATE를 사용하지 않는다. 쓰기는 짧게 유지하고 DB 잠금 실패는 무한 재시도 없이 503과 재시도 안내로 처리한다.
- 해시 계산·정규식·네트워크 작업 중 쓰기 잠금을 유지하지 않는다. 요청 제한 예약/확인과 실패 카운트 갱신을 짧은 별도 트랜잭션으로 처리하고 병렬 시도가 제한을 우회하지 않는지 검증한다.
- LIMIT/OFFSET과 매개변수 바인딩을 사용한다. 한글을 포함한 대소문자 비교는 Python casefold 기반 SQLite 사용자 정의 함수를 각 연결에 등록해 처리한다. 작은 데이터 전체 검색 비용을 문서화한다.
- 순번 SQL 파일과 PRAGMA user_version을 이용한 가벼운 마이그레이션 명령을 사용한다. 초기화와 마이그레이션을 모든 요청에서 반복하지 않는다.
- DB 절대경로는 환경변수로 지정하고 재배포 시 덮어쓰지 않는다. sqlite3 backup API로 수동 백업·복원하며 저장소·정적 경로·임시 디렉터리에 DB를 두지 않는다.

## 12. 실행·배포·인수 계획

로컬 Windows 개발 예시:

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m app.cli migrate
.\.venv\Scripts\python -m app.cli create-admin
.\.venv\Scripts\python -m uvicorn app.main:app --reload
```

위 CLI는 구현 완료했다. app/cli.py에서 실행하며 자세한 운영 예시는 README.md를 따른다.

PythonAnywhere에서는 계정이 지원하는 Python 버전으로 별도 가상환경을 만들고 의존성을 설치한다. API 토큰은 계정에서 생성하며 문서·저장소·채팅에 붙여 넣지 않는다. ASGI 최소 앱 성공 후 DB 경로·운영 보안 설정을 지정하고 마이그레이션·관리자 생성을 수행한다.

공식 ASGI CLI의 배포 명령 형태(구현 시 최신 구문 재확인):

```bash
pa website create --domain YOURUSERNAME.pythonanywhere.com --command '/home/YOURUSERNAME/.virtualenvs/community-demo/bin/uvicorn --app-dir /home/YOURUSERNAME/community-demo --uds ${DOMAIN_SOCKET} app.main:app'
pa website reload --domain YOURUSERNAME.pythonanywhere.com
```

운영에서는 --reload와 다중 워커를 사용하지 않는다. EU 계정은 해당 도메인으로 변경한다. Secure 쿠키·HTTPS·신뢰할 프록시 범위를 확인하고 IP 기반 제한은 실제 전달 경로에 맞춰 검증한다.

추가 완료 조건:

- [ ] 계정에서 무료 ASGI 최소 앱 배포 가능 여부와 비용 없는 사용 조건을 확인한다.
- [ ] 의존성 설치량·DB·로그·백업을 포함한 저장 공간이 무료 한도 안에 있다.
- [ ] 재시작/재배포 후 게시글·세션·규칙·신고 데이터가 유지된다.
- [ ] 정적 파일·API·Secure 쿠키·CSRF·클라이언트 IP 처리·DB 쓰기가 HTTPS 배포 환경에서 동작한다.
- [ ] SQLite 잠금·동시 댓글/삭제·요청 제한·백업 복원 시나리오를 검증한다.
