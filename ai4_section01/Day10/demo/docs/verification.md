## 브라우저 직접 확인

로컬 Uvicorn 서버의 실제 HTML 화면에서 확인했다.

- 회원가입 완료 후 로그인 안내, 로그인 성공 후 환영 화면과 명시적 게시판 진입
- 글 작성·제목 목록·현재 body 상세·댓글 작성
- `<script>` 입력이 실행되지 않고 본문 텍스트로 표시됨
- 신고 사유를 같은 화면에서 입력하여 접수
- 관리자 로그인·규칙 목록·규칙 추가·신고 목록/상세·처리 완료 및 메모 저장
- 새로고침 후 세션·데이터 유지 및 처리 상태 재조회
- 키워드 추가 후 기존 화면 조회에서 마스킹, 비밀번호 재확인 후 원문 편집·저장, 수정 후 재마스킹
- 좁은 브라우저 화면에서 입력과 버튼이 한 열로 배치되고 가로 넘침 없이 사용 가능

증거 화면: [게시판](screenshots/board.png), [관리자 신고 처리](screenshots/admin-report.png).

AUTH-04 비밀번호 찾기는 클라이언트의 명시적인 목업이며 서버 메일 발송 코드가 없다. 관리자 직접 생성은 getpass CLI로 제공하고 테스트용 관리자는 별도 가상 계정으로 생성했다.

## 구현 선택과 한계

- 소규모 앱에 맞춰 라우트는 main.py에 모았고 services/security/filtering/db 모듈로 공통 작업을 분리했다. 별도 ORM이나 프런트 빌드 도구는 없다.
- 신고 사유는 관리자에게만 원문으로 제공한다. 대상 본문은 마스킹하며 일반 사용자에게 관리자 메모를 반환하지 않는다.
- 편집 원문은 작성자에게만 제공한다. 글 편집에는 비밀번호 재확인이 필요하며 댓글 편집에는 세션·소유권을 검증한다.
- 초기 표현 목록은 공개 자료의 명확한 비속어 2개만 선정했다. 최신 자료를 확인했지만 포괄적 은어 사전이 아니며 관리자 확장이 필요하다. 자료·선정 기준·라이선스는 filter-sources.md와 THIRD_PARTY_NOTICES.md에 기록했다.
- 요청 제한은 고정 시간 구간이며 구간 경계 양쪽에서 허용량이 집중될 수 있다. 비밀번호 검증은 동시 실행 예산 예약을 사용하고 성공 시 반환한다.
- SQLite 잠금은 busy timeout 이후 503으로 안내한다. 단일 워커·작은 데이터용이며 고부하 부하 시험은 수행하지 않았다.
- Starlette는 테스트에서 기존 httpx 연동의 사용 중단 예정 경고를 표시한다. 고정 버전 조합의 테스트 결과와 향후 의존성 변경을 구분한다.

## 미실행 사항

PythonAnywhere 계정 접근 권한이 없어 실제 사이트 생성, 무료 ASGI 사용 가능 여부, 계정별 요금/할당량, Linux 설치, 운영 HTTPS/IP 전달, Unix 소켓 실행, 운영 재배포 후 영속성 검증은 미실행이다. 공식 최신 문서를 바탕으로 README와 시작 스크립트를 준비했다. 이것을 배포 성공으로 표시하지 않는다.

복수 프로세스·다중 서버·대규모 전문 검색·SNS·실제 이메일 발송은 이번 범위 밖이다. 실제 DB 원문/백업의 저장 암호화나 모든 최신 비속어 탐지는 구현하지 않았다.
